# 设计文档：储能电站充放计划系统

## 1. 系统概览

```
┌────────────┐   HTTP/JSON   ┌─────────────────┐   SQL   ┌──────────────┐
│ Vue 3 前端  │ ◄──────────► │ Gin 后端 (Go)    │ ◄─────► │ PostgreSQL 16 │
└────────────┘              │  ├─ optimize      │         │ 参数/电价/    │
                            │  │  (SoC 网格 DP) │         │ 计划版本/遥测 │
                            │  ├─ service       │         └──────────────┘
                            │  │  (滚动重排)     │
                            │  └─ store (pg)    │
                            └─────────────────┘
```

- 单座电站，一天 96 个 15 分钟时段。
- 日前：根据次日电价与电站参数生成全天充放计划（版本 1）。
- 运行中：遥测按编号幂等入库、按采集时刻归位；最新遥测与计划偏差超阈值时，
  从其下一时段到日末重新优化，存为新版本，旧版本保留。
- 所有状态入库，服务重启后当前计划版本不变。

## 2. 数学模型

时段 `t = 0..95`，时长 `Δt = 0.25 h`，电价 `p_t`（元/MWh）。决策为各时段电池侧
SoC 变动 `Δ_t`（MWh，正=充电）：

- 充电 `Δ_t > 0`：电网侧取电 `Δ_t/η_c`，成本 `p_t·Δ_t/η_c`；
- 放电 `Δ_t < 0`：电网侧收到 `|Δ_t|·η_d`，收入 `p_t·|Δ_t|·η_d`；
- 折损：按电池侧吞吐量计，每存入或放出 1 MWh 收 `c_deg` 元（约定见 §7）；
- 单时段净收益 `φ_t(Δ)` 是过原点的分段线性凹效用（对收益取负即成本）。

约束：

```
SoC_t = SoC_{t-1} + Δ_t
E_min ≤ SoC_t ≤ E_max            （E_min/E_max = soc_min/soc_max × 额定能量）
0 ≤ Δ_t ≤ η_c·P_c·Δt             （充电）
-P_d·Δt/η_d ≤ Δ_t ≤ 0            （放电）
SoC_96 ≥ end_soc_min × 额定能量   （日末约束）
```

每个时段只选一个目标 SoC（充、放或不动），因此**结构上不可能同时充放**。

目标：最大化 `Σ φ_t(Δ_t)` = 放电收入 − 充电成本 − 折损成本。

## 3. 求解方法：SoC 网格动态规划（选择理由）

候选二选一：

| | SoC 网格 DP（**本系统采用**） | 线性规划（自实现单纯形/内点） |
|---|---|---|
| 精度 | 网格近似，误差有界（§4），网格可加密 | 精确（浮点意义下） |
| 折损成本 | 任意单时段代价函数均可（含非线性、查表） | 只能线性化 |
| 实现 | 后向归纳 + 滑动窗口最大值，约 200 行，O(T·N) | 需自实现并维护一个通用 LP 求解器，复杂且易错 |
| 依赖 | 无 | 无（自实现）或引入外部库 |

选 DP 的理由：

1. **实现直接、可验证**：状态转移就是"从当前 SoC 到可达 SoC"，可用小规模穷举
   在同一网格上逐一对拍（§5），正确性证据强。
2. **可扩展非线性折损**：折损若改为循环次数/吞吐量的非线性函数，只需替换单
   时段代价 `φ_t`；LP 则必须重新线性化。
3. **性能充足**：用单调队列求滑动窗口最大值，每时段 O(N)。默认 N=10000 时
   全天 96 时段求解约几十毫秒，滚动重排（时段更少）更快。
4. 误差上界可解析给出（§4），且可通过加大 N 任意压缩；对本问题（15 分钟
   级计划、遥测噪声远大于网格步长）完全够用。

算法（后向归纳）：令 `V_t(s)` 为从时段 t 初、SoC=s 到日末的最大净收益。

```
V_96(s) = 0            (s ≥ E_end)
        = -∞           (s < E_end)
V_t(s) = max { V_{t+1}(s),                                # 不动
               max_{s'>s, s'-s≤A_c} V_{t+1}(s') - κ_t(s'-s),   # 充电
               max_{s'<s, s-s'≤A_d} V_{t+1}(s') + γ_t(s-s') }  # 放电
κ_t = p_t/η_c + c_deg   （每存入 1 MWh 的净成本）
γ_t = p_t·η_d - c_deg   （每放出 1 MWh 的净收益）
```

对固定的 t，充电候选 `V_{t+1}(s') - κ_t·s'` 只与 s' 有关，因此每个 s 的最优
充电目标是窗口 `(s, s+A_c]` 内的滑动最大值；放电同理。用单调队列在 O(N) 内
求出所有状态的窗口最大值（含 argmax 供策略回放）。平局时严格更优才切换，
偏向"不动"（平坦电价下输出全零计划，符合直觉）。

网格构造：`[E_min, E_max]` 的 N 等分，再精确并入起始 SoC 与日末下限
`E_end`（消除端点取整误差）。起始 SoC 越出上下限时（实际运行可能发生），
首时段必须回到界内，一个时段回不去则报不可行（422）。

## 4. 离散化误差上界

记：

- `δ = (E_max − E_min)/N`：网格步长（MWh）；
- `A_c = η_c·P_c·Δt`、`A_d = P_d·Δt/η_d`：单时段电池侧变动上限，`A = min(A_c, A_d)`，`Â = max(A_c, A_d)`；
- `C = E_max − E_min`：SoC 可行域宽度；
- `M = max_t|p_t| / min(η_c, η_d) + c_deg`：单位电池侧能量对目标函数的最大边际价值
  （`|φ_t` 的斜率`| ≤ M`）；
- `T = 96`：时段数。

**定理**：设 `V*` 为连续最优值、`V_δ` 为网格 DP 最优值，则

```
0 ≤ V* − V_δ ≤ M·δ·(2T·Â/A + C/A)
```

证明（构造性）：

1. **取整**：取连续最优轨迹 `s*_t`，把每个 `s*_t` 向下取整到网格点得 `ŝ_t`。
   网格含 `E_min` 与 `E_end`，故 `ŝ_t ∈ [E_min, E_max]` 且 `ŝ_96 ≥ E_end`。
   每步动作变化 `|Δ̂_t − Δ*_t| = |ε_{t+1} − ε_t| ≤ δ`（`ε_t ∈ [0,δ)` 为取整误差），
   目标损失 `≤ Σ_t M·|ε_{t+1}−ε_t| ≤ T·M·δ`；但 `ŝ` 的动作可能超限时 `δ`，
   即 `ŝ` 仅在放宽限制 `A_x + δ` 下可行。
2. **缩放**：把 `ŝ` 的全部动作乘 `λ = A/(A+δ)`。SoC 轨迹变为
   `s_0 + λ(ŝ_t − s_0)`，是 `s_0` 与 `ŝ_t` 的凸组合，仍在界内；动作满足原限制。
   `φ_t` 过原点分段线性（正齐次），故目标值恰缩为 `λ` 倍，损失
   `≤ (1−λ)|V*| ≤ (δ/A)·T·Â·M = T·M·δ·(Â/A)`。
3. **日末修复**：若 `s_0 < E_end`，缩放可能使日末 SoC 短缺至多
   `(1−λ)(E_end − s_0) ≤ (δ/A)·C`，补充充电修复的代价 `≤ M·δ·C/A`。
   （`s_0 ≥ E_end` 时凸组合天然满足日末约束，此项为 0。）

三项相加即得。`V_δ ≤ V*` 显然（网格是连续问题的限制）。∎

数值示例（默认参数量级）：`E=100 MWh`，soc 10%–95%（`C=85`），`P=50 MW`，
`η=0.9`，`c_deg=10`，`|p|≤1500`：`A_c=11.25`，`A_d≈13.89`，`M≈1677`，
N=10000 时 `δ=0.0085`，上界 ≈ **3.5×10³ 元**（相对日收益万元级 ≤ 几个百分点，
且为保守上界）。网格加密 8 倍，上界缩小 8 倍。

代码中 `optimize.ErrorBound` 按上式计算；测试 `TestGridConvergenceBound`
验证同一算例细网格（8N）与粗网格（N）最优值之差不超过该界。

## 5. 测试策略（与穷举对拍）

`backend/internal/optimize/optimize_test.go`：

- **手算算例**（需求给定）：电价 100/300 两时段，最优充 1 MWh、放 0.81 MWh、
  净收益 143 元；电价 100/120 时最优为不动。断言精确成立。
- **随机小算例对拍**：60 组随机参数（T=2–4 时段、含负电价、随机效率/折损/
  SoC 区间），DP 结果与**同一网格上的无记忆化穷举**（独立实现）比较。
  DP 在网格上是精确的，故允许误差仅为浮点求和顺序差异：
  **相对容差 1e-6**。穷举不可行时 DP 必须同样报不可行。
- **误差界**：25 组随机算例，细网格（8N）与粗网格（N）最优值之差
  `≤ ErrorBound(N)`；且细网格包含粗网格全部节点，最优值不得更小。
- **性质测试**：
  - 电价乘正数 α（折损为 0，或折损同乘 α）：计划逐时段一致、收益 ×α；
  - 电价全天相同且折损非零：最优计划全零；
  - 随机算例的 SoC 轨迹始终在 `[E_min, E_max]` 内、日末不低于下限；
  - 功率上限调大 1.4 倍：最优收益不下降；
  - 功率与 SoC 变动方向一致（结构上不可能同时充放）。

`backend/internal/service/service_test.go`（内存存储）：遥测幂等去重、
晚到遥测按时刻归位且不触发重排、偏差超阈值触发重排且已过去时段不变、
版本号递增、字段级校验错误。

`backend/internal/store/pg/pg_test.go`：PostgreSQL 集成测试（需
`TEST_DATABASE_URL`，未设置则跳过），覆盖版本号原子分配、遥测幂等与归位。

## 6. 滚动修正规则

- **幂等**：遥测按编号（`telemetry.id` 主键）去重，重复上报只算一次。
- **归位**：遥测按采集时刻 `ts` 排序使用；晚到的旧遥测插入历史正确位置。
- **偏差判定**：只依据"采集时刻最新"的遥测。计划 SoC 在任意时刻的值由
  相邻时段末计划值线性插值。`|实际 − 计划| > 阈值` 时触发重排。
- **防重复触发**：每个计划版本记录 `based_on_ts`（其依据的最新遥测时刻）。
  当前计划已覆盖（`latest.ts ≤ based_on_ts`）的遥测不再触发判定。
- **重排范围**：从最新遥测所在时段的**下一时段**到日末（当前时段已部分
  执行，按实测 SoC 作为新起点）；已过去的时段原样保留（不许改）。
- **版本**：重排结果存为新版本（版本号数据库内原子递增），触发原因记录
  遥测编号、偏差与阈值；旧版本全部保留可查。
- **不可行**：若剩余时段内日末约束不可达（如 SoC 过低、时间不够），
  返回 422，旧版本保留。
- **重启**：全部状态在 PostgreSQL，当前版本 = 该日最大版本号，重启不变。

## 7. 约定与边界

- **功率符号**：计划与遥测中功率正=放电、负=充电（电网侧）。
- **折损口径**：按电池侧吞吐量（存入 + 放出，MWh）计 `c_deg` 元/MWh。
- **时区**：计划日按 `PLAN_TZ`（默认 Asia/Shanghai）解释；遥测时刻须带时区
  （RFC3339），换算到计划时区后须落在计划日内，否则拒收（字段 `ts`）。
- **校验**（全部拒收并指出字段）：
  - 效率不在 `(0,1]`：`charge_eff` / `discharge_eff`；
  - `soc_min ≥ soc_max`：`soc_min`；SoC 越出 `[0,1]`：对应字段；
  - 功率为负：`max_charge_mw` / `max_discharge_mw`；能量非正：`energy_mwh`；
  - 折损为负：`degradation_cost_per_mwh`；
  - `end_soc_min` 越出 `[0,1]` 或高于 `soc_max`（必无解）：`end_soc_min`；
  - 电价不是 96 个时段或含非有限数：`prices`；
  - 遥测时刻不属于计划日 / 该日无计划 / SoC 越出 `[0, 额定能量]`：
    `ts` / `soc_mwh`；遥测编号为空：`id`；
  - 日前优化起始 SoC 不在 `[soc_min, soc_max]`：`initial_soc`。

## 8. API 摘要

| 方法 | 路径 | 说明 |
|---|---|---|
| GET/PUT | `/api/station` | 电站参数查询/录入 |
| GET/PUT | `/api/prices/:date` | 96 时段电价查询/录入 |
| POST | `/api/plans/:date/optimize` | 日前优化 `{initial_soc}`，生成新版本 |
| GET | `/api/plans/:date` | 当前计划版本（含 96 时段功率与 SoC） |
| GET | `/api/plans/:date/versions` | 版本列表 |
| GET | `/api/plans/:date/versions/:v` | 指定版本 |
| POST | `/api/plans/:date/telemetry` | 遥测上报 `{id, ts, soc_mwh, power_mw}` |
| GET | `/api/plans/:date/telemetry` | 遥测列表（按时刻归位） |

错误：400 字段校验（`{errors:[{field,message}]}`）、404 不存在、
422 优化不可行、500 其他。
